01 What is REVENANT?

Imagine you run a company with a website, servers, a corporate office network, and a cloud storage account full of customer data. You hire the best security locks, firewalls, and monitoring cameras money can buy. But the real question is: have you actually tested whether any of those protections can be bypassed?

In the real world, organizations hire specialized teams called Red Teams — ethical, authorized security professionals whose entire job is to think and act exactly like a real attacker. They try to break in, expose the weak points, and hand the company a blueprint for fixing them before a criminal does it first.

The problem with human Red Teams is that they are expensive, slow, and limited. A three-person team cannot simultaneously audit a web application, a cloud account, an internal office network, and a mobile API at the same time. Real enterprise environments are too large and change too fast.

REVENANT is an autonomous artificial intelligence platform that acts as an entire Red Team operating simultaneously. It never sleeps, never misses a scan, legally and safely tests every corner of an enterprise's technology stack, and at the end, not only reports the problems but generates the ready-to-use code to fix them. It is an attacker, a detective, an intelligence analyst, and a repair engineer all bundled into one automated system.

02 The Unbreakable Safety Rule: Scope and Authorization

The most important principle in offensive security is this: you can only test systems you are authorized to test. Testing someone else's computer without written permission is illegal in every country on earth.

REVENANT is built around this rule at its very core. It operates with a concept called the Scope Manifest — a digitally signed, legally binding document that the operator provides before any assessment begins. This document lists exactly which web addresses, server IP ranges, cloud accounts, and internal networks are approved for testing. Nothing outside this list will ever be touched, no matter what.

The Scope Engine acts as the permanent gatekeeper of the entire platform. Before any agent, tool, or script sends a single network packet, it asks the Scope Engine: "Is this target on the approved list?" If the answer is no, the action is halted immediately and logged as a scope violation. This happens automatically, even mid-mission, so no human error can accidentally cause an unauthorized test.

flowchart TD A[Operator submits Target and Scope Manifest] --> B{Scope Engine checks the target} B -- Not on approved list --> C[Hard Stop - Action blocked and logged] B -- On approved list --> D[Mission proceeds safely and legally] D --> E[Every sub-action re-checks scope before running] E --> B
Every single action, at every level, passes through the Scope Engine before execution.

03 How REVENANT Thinks: The Blackboard and the Swarm

Most software programs follow a fixed script — Step 1 runs, then Step 2, then Step 3. If Step 2 encounters something unexpected, the entire process stalls or crashes.

REVENANT is fundamentally different. It is built on an architecture called a Stigmergic Multi-Agent Blackboard System. Picture a hospital emergency room. No single doctor manages every procedure by personally directing each nurse one by one. Instead, there is a central patient chart — the Blackboard — that every specialist can read and write to. The cardiologist adds their findings, the radiologist sees them and acts, the anaesthesiologist steps in only when relevant. No one gives orders to anyone else. They all respond to the evolving state of the shared record.

REVENANT's Agents are those expert specialists. When the mission begins, the orchestrator writes the objective on the Blackboard. Agents continuously monitor it and act the moment they see something relevant to their specialization. They post findings back to the board, triggering the next relevant agent, and the cycle continues until the mission is complete.

flowchart TD ORCH[Orchestrator writes mission goal] --> BB[Central Blackboard] BB --> RECON[Recon Agent runs Nmap and Subfinder] RECON --> BB2[Blackboard updated with open ports] BB2 --> WEB[Web Agent runs Katana and Nuclei] WEB --> BB3[Blackboard updated with web vulnerability] BB3 --> CLOUD[Cloud Agent cross-checks cloud posture] CLOUD --> BB4[Blackboard updated with cloud finding] BB4 --> GRAPH[Attack Graph Engine connects all findings] GRAPH --> BB5[Blackboard updated with choke points] BB5 --> REMEDIATE[Remediation Engine generates fix code] REMEDIATE --> REPORT[Reporting Engine compiles deliverables]
Agents never call each other directly — they communicate entirely through the shared Blackboard.

This design has three major advantages. First, agents run in parallel — the web agent and cloud agent work simultaneously without waiting for each other. Second, the mission adapts dynamically — if the recon agent unexpectedly discovers a Kubernetes cluster nobody knew about, the cloud agent steps in automatically. Third, no single failure stops the mission — if one agent errors, the others continue and post their findings independently.

Every REVENANT assessment moves through five distinct phases. Here is exactly what happens at each stage.

05 The Five Mission Profiles

REVENANT does not run the same assessment every time. An operator chooses a Mission Profile at the start, which tells REVENANT which specialist agents to activate and which domains to focus on. Think of profiles as preset camera modes — from a quick portrait shot to a full, high-resolution panoramic exposure.

recon

Surface Mapping

Get an accurate, complete inventory of everything the target exposes to the world before committing to deeper testing. Does not probe for vulnerabilities or attempt any exploitation.

When to use: First look at a new target, or periodic check for new assets that appeared since the last audit.

Tools: Nmap, Subfinder, FFuf
web-dast

Web and API Security Testing

Comprehensively test every web application, API endpoint, and user-facing interface. Includes crawling every page, sending malformed inputs, testing authentication logic, and scanning source code.

cloud-native

ad-identity

Test the internal corporate network's identity infrastructure. Discovers compromisable accounts, hidden paths to administrator access, and certificate authority misconfigurations.

All five domains activated simultaneously. Every agent coordinates concurrently, findings correlate across all domains, and the full attack graph is built from the external entry point to the innermost sensitive resource. Ends with complete remediation and all six reporting formats.

Tools: Every tool in the ecosystem + Attack Graph Engine + Remediation Engine + All six report exporters

06 Every Tool in REVENANT Explained

REVENANT integrates 20+ battle-tested security tools across five operational domains. Rather than building everything from scratch, it wraps each tool in a standardized adapter layer so they all speak the same internal language. Here is every tool, what it does, and why REVENANT uses it.

🌐

Domain 1: Network and Perimeter

Discover what exists before testing anything

Nmap — Network Mapper
Port and Service Discovery

Nmap is the oldest and most trusted network scanning tool in the world. It knocks on every digital door (called a port) and listens for what answers. From the response, Nmap identifies the exact software and version running — for example, "Apache HTTP Server 2.4.49 on port 80." This directly informs which specific vulnerabilities to test for next. Without Nmap, REVENANT would be walking into a building completely blind.

Subfinder — Subdomain Discovery
Attack Surface Enumeration

Large companies do not just have one website. They have dozens of subdomains — separate addresses for different services like mail.company.com, api.company.com, staging.company.com, or admin.company.com. These subdomains are often created for testing and forgotten, left unpatched and vulnerable. Subfinder scours public internet records, certificate transparency logs, and DNS databases to build a complete list of every subdomain associated with a target domain. REVENANT uses this as the foundation of its perimeter map.

FFuf — Web Directory Fuzzing
Hidden Endpoint Discovery

Even after mapping known subdomains, hidden content often lurks behind unlisted URLs. FFuf rapidly fires thousands of web address guesses per second using wordlists (pre-built lists of common directory and file names) to discover pages not linked anywhere publicly — like /admin, /backup, /config.php, or /.git. These hidden paths often contain sensitive information or outdated software that becomes an easy entry point.

🔬

Domain 2: Web and Application Security

Probe every user-facing surface for exploitable flaws

Katana — Web Crawler
Sitemap Generation

Before you can test a web application for vulnerabilities, you need to know every page, form, button, and API endpoint it has. Katana is a high-speed automated browser that navigates websites the way a human would — clicking links, submitting forms, following redirects — but at machine speed, mapping every reachable endpoint in seconds. REVENANT uses Katana to create the complete sitemap so every subsequent scanner knows exactly what to test.

Nuclei — Template-Based Vulnerability Scanner
Known Vulnerability Detection

Nuclei uses a library of thousands of community-written templates — each one a precise test for a specific known vulnerability, misconfiguration, or security weakness. When REVENANT runs Nuclei against a discovered web service, it simultaneously fires hundreds of targeted checks: Is this server running software with a known CVE? Is the security header misconfigured? Does this endpoint expose debug information? Is there an admin panel with default credentials? Nuclei is REVENANT's rapid, comprehensive first pass at finding low-hanging fruit across the entire web surface.

Semgrep — Static Application Security Testing
Source Code Analysis (SAST)

While Nuclei tests running applications from the outside, Semgrep reads source code from the inside. It scans code line by line using pattern-matching rules to find insecure coding patterns before the software is even deployed — SQL queries that concatenate user input directly (SQL injection risk), hardcoded API keys, dangerous cryptographic functions, or missing input validation. REVENANT uses Semgrep when source code is available, giving it visibility into vulnerabilities invisible from the outside.

Schemathesis — API Property-Based Fuzzing
OpenAPI Correctness Testing

Modern web services expose APIs that document their expected inputs using OpenAPI specifications. Schemathesis reads these specifications and then systematically feeds the API unexpected inputs — extreme values, empty strings, special characters, reversed data types — to expose edge cases where the API crashes, exposes internal errors, or returns data it should not. This is called property-based fuzzing, and it catches logical flaws that rule-based scanners completely miss.

Native DAST Adapter — In-Process Web Fuzzer
Custom Dynamic Testing Engine

In addition to wrapping external tools, REVENANT includes its own built-in dynamic testing engine written in Python. This adapter directly tests for three critical web vulnerability classes: Cross-Site Scripting (XSS, where malicious scripts are injected into web pages), Open Redirects (where an attacker tricks a website into sending users to a malicious address), and Path Traversal (where attackers navigate outside the web application's intended directories to read server files). Unlike external tools, this adapter can be precisely tuned without depending on third-party releases.

☁️

Domain 3: Cloud and Container Security

Audit cloud accounts and container infrastructure against global benchmarks

Trivy — Container and Infrastructure Vulnerability Scanner
CVE and Misconfiguration Detection

Modern applications are packaged into "containers" — isolated bundles of software that can run consistently anywhere. These containers are built from "images" that often include operating system packages, libraries, and dependencies. If those components have known security vulnerabilities (CVEs), the container is a liability. Trivy scans container images, file systems, and infrastructure-as-code configurations to detect known CVEs, misconfigurations, and sensitive data.

Prowler — Cloud Security Posture Management
AWS and Azure Benchmark Auditing

Prowler audits cloud accounts against hundreds of security checks derived from global standards like the CIS Benchmark, SOC 2, and GDPR requirements. It answers questions like: Are any S3 storage buckets publicly readable? Is multi-factor authentication enforced on all administrator accounts? Are security groups allowing unrestricted inbound traffic from the entire internet? Is CloudTrail logging disabled? Prowler gives REVENANT a comprehensive, benchmark-scored view of an organization's cloud security posture.

Checkov — Infrastructure-as-Code Security Scanner
Pre-Deployment Configuration Analysis

Modern cloud infrastructure is defined in code files — Terraform scripts, CloudFormation templates, Kubernetes YAML manifests. Checkov scans these files before they are deployed to catch misconfigurations at the blueprint stage — for example, a Terraform file that will create a database with no encryption, or a Kubernetes manifest that will create a container running as the root user. REVENANT uses Checkov to catch cloud security problems before they ever reach production.

Kubescape and Kube-bench — Kubernetes Security Hardening
CIS Kubernetes Benchmark Validation

Kubernetes is the dominant platform for orchestrating containers at scale. Misconfigured Kubernetes clusters are extremely common and extremely dangerous — a container that escapes its sandbox can compromise the entire host machine. Kubescape evaluates cluster configurations against NSA/CISA Kubernetes Hardening Guidance. Kube-bench checks every node against the CIS Kubernetes Benchmark. Together they give REVENANT a complete compliance picture of the cluster's security posture.

Falco — Runtime Security and Anomaly Detection
Live Container Intrusion Detection

Falco monitors running containers in real time, watching for behavioral anomalies that indicate something has gone wrong: a web server process suddenly opening a shell, a container reading system password files, a process establishing an outbound connection to an unknown IP address. While the other cloud tools audit configuration, Falco catches active threats happening live. In REVENANT's purple team mode, Falco verifies whether an organization's runtime detection is working as expected.

Domain 4: Identity and Active Directory

Expose hidden privilege paths inside corporate networks

NetExec — Network Credential Validation
Password Reuse and Lateral Movement Testing

NetExec is the modern successor to the legendary CrackMapExec tool. It tests whether a set of credentials — perhaps discovered through a phishing simulation or a credential dump — can be used to authenticate against multiple services on an internal corporate network simultaneously. Services tested include SMB file shares, RDP remote desktop, WinRM management, and LDAP directory services. This reveals whether an organization suffers from password reuse across multiple systems, one of the most common ways attackers pivot through corporate networks.

BloodHound — Active Directory Attack Path Mapping
Privilege Escalation Graph Analysis

Active Directory manages which employee accounts can access which computers, servers, and resources. BloodHound ingests all of Active Directory's relationships — users, groups, computers, permissions, and trust links — and maps them into a visual web. It then runs graph algorithms to find non-obvious paths from a low-privilege user account all the way to Domain Administrator. These paths often involve obscure permission delegations that no human administrator would think to audit. REVENANT uses BloodHound to reveal the invisible attack highways inside corporate networks.

Certipy — Active Directory Certificate Services Auditing
AD CS Misconfiguration Detection (ESC1-ESC8)

Many organizations run their own internal certificate authority using Microsoft Active Directory Certificate Services (AD CS). AD CS is notoriously difficult to configure securely, and misconfigurations — classified as ESC1 through ESC8 — can allow a low-privilege account to request a certificate that authenticates it as a Domain Administrator. Certipy automatically enumerates the certificate templates, authority configurations, and permissions in an AD CS environment and flags which specific misconfigurations are present.

Domain 5: Forensics, Malware, and Threat Simulation

Detect threats, analyze malware, and simulate nation-state attack techniques

YARA — Malware Pattern Matching
File and Memory Signature Detection

YARA is the industry standard for writing rules that describe malicious software. Each YARA rule is a signature — a set of strings, byte patterns, and logical conditions that identify a specific piece of malware, a webshell, or a hacking tool. REVENANT uses YARA to scan files and memory regions against libraries of thousands of rules covering known ransomware, remote access trojans, and web shells. REVENANT also auto-generates new YARA rules for the specific malware artifacts it simulates during an engagement.

Volatility 3 — Memory Forensics
RAM Dump Analysis

Sophisticated attackers and modern malware often operate entirely in RAM — they never write any files to the hard drive, making them invisible to traditional antivirus software. Volatility analyzes a snapshot (dump) of a computer's RAM and can extract running processes, network connections, loaded kernel modules, encryption keys, command histories, and injected malicious code — all without ever touching the hard disk. REVENANT uses Volatility when memory analysis of a potentially compromised system is required.

Velociraptor — Live Endpoint Forensics and Triage
Fleet-Scale Incident Investigation

Where Volatility analyzes memory dumps from individual computers, Velociraptor can simultaneously interrogate thousands of live machines across an entire organization using VQL (Velociraptor Query Language). It can answer questions like: "Show me every machine that ran this executable in the last 48 hours," or "List all machines with a suspicious new service installed." REVENANT uses Velociraptor for enterprise-scale incident triage and to validate that indicators of compromise are properly visible to the organization's detection tooling.

Binwalk — Firmware Analysis
IoT and Embedded System Security

When REVENANT operates in firmware security mode (relevant for IoT devices, network appliances, and embedded systems), Binwalk extracts, decompresses, and analyzes firmware binary images. It identifies embedded file systems, configuration files, encryption keys, and known vulnerable libraries packed inside firmware. This is critical for hardware security assessments where the "software" being tested is burned into a physical device.

CAPEv2 — Malware Sandbox and Dynamic Analysis
Behavioral Malware Profiling

CAPEv2 is a malware analysis sandbox. When a suspicious file or payload needs to be analyzed, CAPEv2 runs it in an isolated, instrumented virtual machine and records everything the malware does: which files it creates, which registry keys it modifies, which network connections it makes, which processes it launches or injects into. REVENANT uses CAPEv2 to dynamically profile custom payloads generated during engagements, producing behavioral reports that inform detection rule generation.

Atomic Red Team — Adversary Technique Simulation
MITRE ATT&CK Technique Emulation

Atomic Red Team is a library of small, focused test scripts — called "atomics" — each of which simulates one specific attacker technique catalogued in the MITRE ATT&CK framework. For example, an atomic for T1059 simulates malicious command-line execution; an atomic for T1003 simulates credential dumping. REVENANT executes these atomics in a controlled manner to test whether an organization's endpoint detection and SIEM alarms actually fire correctly when real attacker behaviors occur.

Caldera — Automated Adversary Emulation
Full APT Campaign Simulation

Caldera takes adversary simulation further than individual atomics. It is a full adversary emulation platform that can deploy autonomous agents on target machines, chain multiple ATT&CK techniques together into complete campaigns, and adapt its behavior based on what it discovers. REVENANT integrates with Caldera to run multi-stage attack simulations — for example, simulating an entire APT campaign from initial access through lateral movement, privilege escalation, and data exfiltration.

07 The Adapter System: How REVENANT Controls Every Tool Without Breaking

Each of the 20+ tools above speaks a completely different language. Nmap outputs XML. YARA outputs custom text. Katana streams JSON lines. Nuclei uses a structured template format. If REVENANT had to write unique parsing code for every tool's output, the system would be impossible to maintain.

The Adapter System solves this by giving every tool an identical four-step wrapper. Think of it as a universal translator. No matter what language a tool speaks natively, its adapter converts everything into a single, clean standard that the rest of REVENANT understands perfectly.

flowchart LR S1["Scope Validation\nIs the target authorized?\nIf not, hard stop."] --> S2 S2["Command Construction\nBuild the exact CLI command\nwith correct flags and targets."] --> S3 S3["Safe Execution\nRun the tool in isolation.\nCapture all raw output."] --> S4 S4["Output Standardization\nParse raw text, XML, or JSON.\nConvert into a uniform Finding record."]
Every tool — regardless of its native output format — produces the same standardized Finding record at the end.

The output of Step 4 is always a Finding object. Here is what a standardized Finding record looks like:

title:Outdated Apache HTTP Server with Known Remote Code Execution (CVE-2021-41773)
description:Path traversal and RCE vulnerability in Apache 2.4.49. Allows unauthenticated file read and code execution.
location:http://target.company.com:80 — Apache/2.4.49
severity:Critical
mitre_technique:T1190 — Exploit Public-Facing Application
discovered_by:nmap_adapter + nuclei_adapter

Because every single tool outputs identical Finding records, the blackboard, attack graph engine, remediation engine, and reporting engine never need to know which tool found a given issue. The system is fully modular — new tools can be added by writing one new adapter, and the rest of the platform automatically benefits.

08 The Attack Graph and Choke Point Engine

This is the capability that fundamentally separates REVENANT from a collection of automated scanners. Any scanner can find individual vulnerabilities. REVENANT finds the narrative — the story of how an attacker would move through your environment from beginning to end.

The Core Problem: Lists vs. Graphs

Traditional security reports deliver a list of findings sorted by severity. The team patches the "Critical" items first, then works down the list. This sounds logical but is deeply flawed. Many devastating breaches are assembled from entirely "Low" and "Medium" severity findings that, in isolation, seem harmless.

Real attackers do not see a list. They see a graph of trust relationships. They ask: "What can I reach from here? What does this access give me? How do I get from this low-privilege position to that high-value target?"

How REVENANT Builds the Graph

After all agents complete their probing, REVENANT's Attack Graph Engine ingests every Finding from the blackboard and constructs a mathematical graph where nodes represent assets and findings, and edges represent exploitable relationships between them. It then applies graph traversal algorithms to discover every possible attack path from the external internet to each sensitive target.

flowchart LR ATK[External Attacker] --> F1 F1[Forgotten subdomain discovered\nstaging.company.com\nSeverity: Low] --> F2 F2[Outdated PHP version on that subdomain\nSeverity: Medium] --> F3 F3[Default admin credentials still active\nSeverity: Low] --> F4 F4[Full access to customer database\nSeverity: Critical] F2 --> CP[CHOKE POINT\nFix the PHP version here.\nSteps 3 and 4 become unreachable.\nEntire chain collapses.]
Four Low or Medium findings chain into a Critical breach. The Choke Point breaks the entire sequence at one single fix.

The Choke Point Calculation

Once all attack paths are mapped, REVENANT calculates which single node, if hardened, eliminates the greatest number of distinct attack paths simultaneously. This is the Choke Point. Security teams receive a ranked, prioritized action list: fix this one thing first because it neutralizes five attack routes at once.

Think of it like a city's water supply. You could repair every individual leaking pipe across the city — which takes months and enormous resources. Or, if you identify the one main valve that feeds sixty percent of those leaking pipes, you turn that one valve and stop the majority of the leaks in seconds.

Choke Points transform remediation from an overwhelming 200-item list into a focused, high-impact action plan. Maximum security improvement for minimum engineering effort.

09 The Autonomous Remediation Engine

Most security platforms hand you the problem and leave you to figure out the solution. REVENANT does not stop at discovery. For every confirmed vulnerability, the Remediation Engine synthesizes production-ready defense code tailored to the exact technology stack involved.

flowchart TD FINDING[Confirmed Vulnerability arrives from Blackboard] --> REM[Autonomous Remediation Engine] REM --> TF[Terraform patch\nLocks down cloud storage\nCloses firewall openings\nRestricts IAM permissions] REM --> K8S[Kubernetes NetworkPolicy\nCreates default-deny rules\nIsolates container traffic\nEnforces pod security] REM --> ANS[Ansible playbook\nDisables SMBv1 and Telnet\nEnforces SSH key auth\nRemoves default accounts] REM --> SIG[Sigma detection rule\nDescribes attack behavior\nPlugs into Splunk and Elastic\nAlerts on future attempts] REM --> YAR[YARA signature rule\nMatches malware patterns\nDeploys to endpoint security\nCatches same malware again]
A single confirmed vulnerability triggers five categories of automated defense artifacts.

Terraform patches are cloud infrastructure code. They describe the corrected state of a cloud resource — exactly how an S3 bucket should be configured to be private, or exactly how an IAM role should be scoped to only the permissions it actually needs. Engineers apply these directly through their standard cloud deployment pipeline.

Kubernetes manifests define network boundary policies for container environments. A generated NetworkPolicy file explicitly states which containers are allowed to communicate with which other containers, and denies everything else by default. This prevents a compromised container from freely reaching other internal services.

Ansible playbooks are server automation scripts describing system-level hardening actions — disabling old insecure protocols like SMBv1, enforcing encrypted SSH authentication, removing default user accounts, and applying CIS benchmark configurations — executable across an entire fleet of servers with a single command.

Sigma rules are vendor-neutral detection rule specifications. They describe the behavioral pattern of an attack technique in a structured format that can be automatically converted to work with any major security monitoring platform — Splunk, Microsoft Sentinel, Elastic SIEM, IBM QRadar, and others.

YARA rules are file and memory signature rules deployed to endpoint detection tools. They fingerprint the specific malware artifacts, payloads, or webshells involved in the engagement so that future instances of the same malicious file are automatically detected anywhere in the organization.

10 How You Interact With REVENANT

REVENANT is designed for two modes of operation.

Direct Command-Line Mode

For individual engineers and security consultants running targeted assessments. A single command specifying the target, the scope manifest file, and the desired profile launches the entire platform. All results are saved to a local evidence directory. This mode is fast, portable, and requires no infrastructure beyond a Python environment.

Appliance Mode

For enterprise security operations teams. REVENANT is deployed as a containerized appliance using Docker Compose, running continuously in the background. In this mode, it exposes a REST API that allows other systems to trigger scans programmatically, schedule recurring assessments, integrate findings directly into vulnerability management dashboards, and send alerts to SOAR platforms like Splunk Phantom or Cortex XSOAR when critical findings are confirmed.

13 Glossary — Every Key Term in Plain English

Red Team
An authorized ethical team that simulates real attackers to expose weaknesses before criminals do.
Blue Team
The defense team that monitors systems, detects threats, and responds to incidents.
Purple Team
A collaborative exercise where Red and Blue teams work together to test attack simulations and tune detection responses simultaneously.
Scope Manifest
A signed, legally binding document defining exactly which systems are authorized for testing. Nothing outside this list is touched.
Blackboard
The central shared memory that all autonomous agents read from and write to without communicating directly with each other.
Agent
An autonomous software specialist that monitors the blackboard and acts on findings relevant to its domain.
SAST
Static Application Security Testing — scanning source code without running it to find insecure patterns.
DAST
Dynamic Application Security Testing — probing a running application from the outside by sending it real traffic.
CVE
Common Vulnerabilities and Exposures — a globally numbered database of known software security flaws.
CIS Benchmark
Center for Internet Security Benchmark — globally recognized configuration standards for securely setting up systems and cloud services.
MITRE ATT&CK
A globally recognized framework cataloguing every technique real-world attackers use, organized by tactic.
Attack Graph
A mathematical map of all the paths an attacker could take through a network from entry point to sensitive target.
Choke Point
The single most impactful node in the attack graph — fixing it collapses the most attack paths simultaneously.
Remediation
The process of repairing a vulnerability — in REVENANT's case, by generating ready-to-deploy fix code automatically.
SARIF
Static Analysis Results Interchange Format — a standard machine-readable format for security findings used by developer tooling like GitHub and VS Code.
Sigma
A vendor-neutral detection rule language that can be converted to work with any SIEM platform — Splunk, Sentinel, Elastic, and others.
YARA
A pattern-matching language used to write signatures that identify malware, webshells, and hacking tools in files and memory.
Terraform
Infrastructure-as-Code tool that defines and deploys cloud resources through configuration files. Used by REVENANT to generate cloud fix code.
Ansible
An automation tool that applies system configuration changes across servers using human-readable playbook files.
Kubernetes
A platform for running and orchestrating containerized applications at scale. Used extensively in modern cloud infrastructure.
Active Directory
Microsoft's corporate identity management system — manages users, computers, groups, and permissions in an office network.
SOAR
Security Orchestration, Automation and Response — platforms that automate security alert triage and incident response workflows.
EDR
Endpoint Detection and Response — security software running on individual computers that monitors for and responds to malicious activity.
SIEM
Security Information and Event Management — a centralized platform that collects, stores, and analyzes security logs from across the organization.
